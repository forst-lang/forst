```typescript
import { VerifyPassword } from "@forst/gen/auth";
import type { VerifyPasswordRequest } from "@forst/gen/auth";

const input: VerifyPasswordRequest = {
  plainPassword: "secret",
  passwordHash: "$2a$...",
};

const { valid } = await VerifyPassword(input);
```

To call functions at runtime, see [Call Forst from Node](/interop/node/call-forst). To call legacy JavaScript from compiled Forst, see [Call JavaScript from Forst](/interop/node/call-javascript).

## What you get

Each Forst package becomes a subpath under `@forst/gen`:

| Forst package | Import |
| --- | --- |
| `package auth` | `@forst/gen/auth` |
| `package auth` | `@forst/gen/auth` |

Types for that package export from the same subpath. Shared shapes also re-export from `@forst/gen`.

```typescript
import type { VerifyPasswordRequest } from "@forst/gen/auth";
// or
import type { VerifyPasswordRequest } from "@forst/gen";
```

Output on disk (default):

```text
.forst/client/          gitignored, regenerated, linked into node_modules
```

`forst generate` writes `node_modules/@forst/gen` → `.forst/client` so the specifier resolves. Full output modes and every `generate` field are on the [CLI reference](/workflow/cli#generate-configuration).

## Discovery with `ftconfig.json`

`forst generate` and `forst dev` share **include/exclude** rules from `ftconfig.json`:

```json
{
  "files": {
    "include": ["**/*.ft"],
    "exclude": [
      "**/node_modules/**",
      "**/.git/**"
    ]
  }
}
```

Pass **`-config`** explicitly or let the CLI search upward from your target directory.

## End-to-end example

The **tictactoe** example regenerates the client after you change `.ft` files:

```bash
task example:tictactoe:generate
```

See [`examples/in/tictactoe/`](https://github.com/forst-lang/forst/tree/main/examples/in/tictactoe) and [`examples/client-integration/`](https://github.com/forst-lang/forst/tree/main/examples/client-integration).

## Caveats

### Structure only in TypeScript

Generated types reflect field names and TypeScript shapes. They do **not** carry runtime rules like **`String.Min(1)`** or **`Int.Max(99)`**. Add client validation yourself, or call the Forst server which validates at the boundary.

### Provider gated exports

Functions that need wired **`Providers(f)`** are excluded from TypeScript emit. The invoke wire stays payload only. See [Providers § Caveats](/language/providers#caveats).

### Nominal error tags

TypeScript **`_tag`** export for nominal Forst errors is still maturing. Treat those payloads as evolving. Invoke transport failures (`InvokeRejected`, …) already use stable tags. See [Errors and Result § Caveats](/language/errors-and-result#caveats) and [Call Forst from Node](/interop/node/call-forst#failures).
