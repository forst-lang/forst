Install `@forst/cli` or a native binary ([Installation](/installation)), then compile a file:

```bash
npx forst path/to/hello.ft
```

The **`forst`** CLI transpiles `.ft` sources, runs programs, generates the TypeScript client package, and starts development services.

Node apps that import `@forst/gen` also need the `postinstall` generate script. See
[Installation § Generated TypeScript client](/installation#generated-typescript-client).

## Default compile and run

With no subcommand, `forst` compiles a single `.ft` file. Given `hello.ft`:

<HelloFt />

Run it with:

```bash
forst path/to/file.ft          # compile
forst run path/to/file.ft      # compile, build, and run
forst build path/to/file.ft    # compile and build only
```

Common flags (see `forst --help`):

| Flag | Purpose |
| --- | --- |
| `-root <dir>` | Merge same-package `.ft` files under a directory tree |
| `-export-struct-fields` | Emit exported struct fields with `json` tags for `encoding/json` |
| `-log-level` | `trace`, `debug`, `info`, `warn`, `error` |
| `-watch` | Recompile on file changes |

## `forst generate`

Emit a TypeScript client package from Forst sources:

```bash
forst generate .
forst generate ./my-service
forst generate -config ./ftconfig.json ./my-service
forst generate --watch .
```

Uses the same file discovery rules as `forst dev`. Import from `@forst/gen/<package>` after generate (and after `postinstall` on a fresh machine).

`--watch` regenerates when `.ft` files change. Use it when the dev server runs separately, or rely on regenerate-on-save from [Dev server](/workflow/dev-server#generated-client).

### Output modes

| Mode | `outDir` | Committed | Linked into `node_modules` |
| --- | --- | --- | --- |
| Ephemeral (default) | `.forst/client` | No | Yes (`node_modules/@forst/gen` → outDir) |
| Committed | for example `packages/forst-client` | Yes | No (`link: "auto"` skips linking outside `.forst`) |

Ephemeral output is removed by `forst clean` and restored by the next generate. Committed mode is a normal workspace package you check in.

### Generate configuration

Set these under `"generate"` in `ftconfig.json`:

```json
{
  "generate": {
    "packageName": "@forst/gen",
    "outDir": ".forst/client",
    "link": "auto",
    "emit": "js",
    "testingSubpath": "testing",
    "effect": false,
    "ssrModule": ""
  }
}
```

| Field | Type | Default | Purpose |
| --- | --- | --- | --- |
| `packageName` | `string` | `"@forst/gen"` | Name written into the generated `package.json` and used as the `node_modules` link name |
| `outDir` | `string` | `.forst/client` | Single output directory relative to the ftconfig boundary root |
| `link` | `"auto"` \| `"always"` \| `"never"` | `"auto"` | Whether to write the `node_modules` link. `auto` links when `outDir` is inside `.forst` |
| `emit` | `"js"` | `"js"` | Always emit built JS. `"ts"` is rejected |
| `testingSubpath` | `string` | `"testing"` | Subpath key for the test scope (`@forst/gen/testing`). Change it when a Forst package is named `testing` |
| `effect` | `bool` | `false` | When `true`, every generated function returns an `Effect` instead of a `Promise`. See [Effect mode](/interop/node/effect) |
| `ssrModule` | `string` | `""` (off) | Optional path for a legacy SSR wrapper module. Empty means do not write one |

Task pages link here instead of repeating this table.

## `forst dev`

Start the HTTP development server for function discovery, invocation, and types:

```bash
forst dev -root ./my-service -port 8080
forst dev -config ./ftconfig.json -root .
```

See [Dev server](/workflow/dev-server).

## `forst lsp`

Start the language server (JSON-RPC over HTTP on `POST /`):

```bash
forst lsp -port 8081 -log-level info
```

Used by the VS Code extension. This is HTTP LSP rather than stdio. Other editors need a similar bridge.

## `forst fmt`

Format `.ft` sources:

```bash
forst fmt path/to/file.ft
```

## `forst test`

Run Forst tests (discovery and emit bridge):

```bash
forst test ./...
```

## `forst dump`

Debug compiler phases (lexer, parser, typechecker, transformer):

```bash
forst dump --file path/to/file.ft --format pretty
forst dump --file path/to/file.ft --phase typechecker
```

Useful when reporting compiler bugs.

## `forst clean`

Remove compiler-generated artifacts under `.forst/` (run sandboxes, the generated client, test emit dirs, executor temp modules, nodert sockets, invoke ready markers). User config such as `.forst-gomod/` is not removed.

```bash
forst clean
forst clean -root ./my-service
forst clean -dry-run
```

After `forst clean`, run `forst generate` (or rely on `postinstall`) to restore `@forst/gen`.

## `forst version`

Print compiler version info:

```bash
forst version
forst --version
```

Prints semver, commit, and build date.

## npm wrapper

When installed via `@forst/cli`:

```bash
npx forst run hello.ft
npx forst --forst-cli-info    # package version, binary path, compiler version
```

Set **`FORST_BINARY`** to skip download in CI.
